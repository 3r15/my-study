# 모의고사 제작 문항 원본

`data/mock-bank.json` 의 원본입니다. 과목별로 나눠 두었습니다.

| 파일 | 과목 | 문항 |
|---|---|---|
| `bank1.json` | 1과목 (운영체제·네트워크·소프트웨어공학·객체지향·테스트) | 20 |
| `bank2.json` | 2과목 (C·Python·객체지향·모듈·보안) | 20 |
| `bank3.json` | 3과목 (자료구조·DB·SQL) | 26 |

요약집 193항목의 내용과 12회차 기출의 출제 경향을 근거로 새로 작성했습니다.
`sec` 는 근거가 된 핵심요약 항목 번호이며, 빌드 때 이 번호로 과목·단원·항목 제목을 채웁니다.

## 스키마

```json
{ "id":"M01", "sec":4,
  "q":"문제 지문", "code":"코드 (없으면 생략)",
  "options":["보기1","보기2","보기3","보기4"], "answer":3,
  "why":"정답 해설",
  "notes":["①을 고른 사람이 착각한 것","","",""] }
```

`notes[i]` 는 i+1번 보기에 대한 짚어보기이고, 빈 문자열이면 화면에 표시하지 않습니다.

- **긍정형**("옳은 것은?") — 오답 보기마다 무엇을 착각한 것인지 적고, 정답 보기는 빈 문자열
- **부정형**("옳지 않은 것은?") — 정답 보기(= 틀린 설명)에 왜 틀렸는지를 적는다

빌드 스크립트가 정답 위치에 note 가 있는지로 부정형을 판별해 `neg` 플래그를 붙이고,
화면에서 "이 보기가 틀린 설명입니다"를 앞에 붙여 줍니다.

## 빌드

```bash
python build/mock/build_bank.py     # bank*.json → data/mock-bank.json
```

검증 항목: id 중복, 보기 4개, 보기 문구 중복, answer 범위(1~4), notes 4개,
`sec` 가 실제 요약 항목인지, `why` 유무, 보기 설명이 하나라도 있는지.
